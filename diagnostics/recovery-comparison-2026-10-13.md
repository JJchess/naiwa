## 为什么可能出现一部分人通、一部分人不通

DNS 解析器会缓存地址、负责解析的服务器名单，也会缓存“名称不存在 / 没有这类记录”的结果，避免每次访问都重新查询。缓存存在有效期 TTL，且各网络获取缓存的时刻不同。因此刚新建或迁移域名时，校园网、运营商和浏览器可能暂时保留不同结果。负缓存 TTL 通常取 SOA TTL 与 SOA MINIMUM 的较小值，随时间递减，过期后不得继续使用该负缓存。[RFC 2308：负缓存](https://www.rfc-editor.org/rfc/rfc2308)

这不是让网页文件慢慢传到每一部手机，而是不同解析器在不同时间重新询问域名信息。对我们这个域名，有当天从阿里 DNS 切到 Cloudflare 的操作记录，且实测旧阿里两台权威没有 A、新 Cloudflare 两台权威有 A，确实存在迁移期间新旧信息不同步。旧阿里 NODATA 的负缓存 TTL 为 600 秒，父区委派 TTL 为 172800 秒；二者是不同缓存，不代表手机错误一定持续其中某个时长。

用户手机显示的正确域名 NXDOMAIN，与我们查询旧阿里得到的 NOERROR / NODATA 并不相同。我们没有捕获手机当时使用的 DNS 服务器、完整回包及 TTL，所以**自行恢复与缓存更新相符，但尚不能证明这就是该手机 NXDOMAIN 的唯一原因**。

## 与中国奶龙大学.com 的实际差异

| 项目 | 奶蛙职业技术学院.com | 中国奶龙大学.com |
| --- | --- | --- |
| 当前 NS | ashton / stephane.ns.cloudflare.com | nsc1–4.squarespacedns.com |
| 当前 A | 104.21.28.129、172.67.146.49 | 198.185.159.144、198.185.159.145、198.49.23.144、198.49.23.145 |
| 注册时间，北京时间 | 2026-10-13 13:57:34 | 2026-10-12 16:48:15 |
| 注册局 last changed，北京时间 | 2026-10-13 17:24:43 | 2026-10-12 23:10:50 |

注册局 `last changed` 只代表域名对象变更，不一定是 NS 修改。它不能用于推算某次 DNS 迁移的准确时间。对方域名早约 21 小时注册、目前使用不同 DNS 服务，这些是事实；“它已完成传播所以从不出问题”没有充分证据。我们只知道用户访问它时成功，没有它上线时的完整失败记录。

当前情况不能证明中文域名本身有问题，也不能证明 Cloudflare 一定比对方供应商差。更有依据的解释是：我们明确经历了刚注册及 DNS 迁移，且新旧权威数据不一致；对方是否经历同类窗口未知。

原始证据已存本目录 `comparison-*.json`。注册局一手数据：[奶蛙 RDAP](https://rdap.verisign.com/com/v1/domain/xn--vhqt0ztpb01mkjgbk6bnujgj4a.com)、[奶龙 RDAP](https://rdap.verisign.com/com/v1/domain/xn--fiqs8srwb9iv6f6w9n.com)。

## 后续怎么减少复发

当前已恢复，保持正在工作的 NS 配置即可，不反复切换。以后迁移 DNS 时先在新服务商配置并验证相同记录，切换后保留旧 DNS 的有效记录一段过渡期，使缓存旧委派的人也能访问。降低页面 A 记录 TTL 不能直接清除已经被缓存的父区 NS 或 NXDOMAIN。[阿里云 DNS 迁移说明](https://help.aliyun.com/zh/dns/pubz-dns-server-related-faq)
